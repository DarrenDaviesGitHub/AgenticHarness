# Api layer rules

- Controllers only map and send: request record -> command/query -> `sender.Send(...)` -> HTTP result. No business logic, no repositories, no `DbContext`, no try/catch.
- Controllers are `sealed`, inherit `ControllerBase`, use `[ApiController]`, an explicit `[Route("api/<plural>")]`, and inject only `ISender` through the primary constructor.
- Action names end in `Async` (`SuppressAsyncSuffixInActionNames` is off) so `CreatedAtAction(nameof(GetByIdAsync), ...)` works.
- Every action has XML doc comments (`<summary>`, `<param>`, `<response code="...">`) and one generic `[ProducesResponseType<T>(status, contentType)]` per status code it can return. Errors use `ProblemDetails`/`ValidationProblemDetails` with `"application/problem+json"`.
- Status codes: GET 200, POST 201 + `CreatedAtAction` Location, PUT/DELETE 204, validation 400, missing 404, conflict 409. Route ids use `{id:guid}`.
- Request bodies are separate `sealed record`s in `Contracts/` with a `ToCommand(...)` mapper. Never bind commands directly.
- Map new exception types to status codes only in `ExceptionHandling/GlobalExceptionHandler.cs`; responses must stay RFC 9457 ProblemDetails.
- Keep `Program.cs` under 40 lines; register services in `AddPresentation()`, `AddApplication()`, `AddInfrastructure()`.
- `docs/openapi.json` is regenerated by `dotnet build`. Commit it with the code change; never edit it by hand.
- Add every new endpoint to `Ardent.Project.Api.http` and to the integration tests.
